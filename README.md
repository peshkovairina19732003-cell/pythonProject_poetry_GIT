# ** Проект "Банковские операции" **

## Описание
Проект представляет собой набор утилит для обработки данных о банковских операциях. Он позволяет фильтровать операции по статусу и сортировать их по дате, что является основой для клиентского виджета.

## Использование
### Основной функционал реализован в модуле src/processing.py.

### Фильтрация по статусу (filter_by_state)
Функция отбирает операции с заданным статусом.

~~~
from src.processing import filter_by_state

operations = [{'id': 1, 'state': 'EXECUTED'}, {'id': 2, 'state': 'CANCELED'}]
executed = filter_by_state(operations) # По умолчанию ищет 'EXECUTED'
~~~
Сортировка по дате (sort_by_date)
Функция сортирует операции по полю date.

~~~
from src.processing import sort_by_date

sorted_ops = sort_by_date(operations) # По убыванию (новые -> старые)
sorted_ops_asc = sort_by_date(operations, reverse=False) # По возрастанию (старые -> новые)
~~~

### Декоратор логирования log

Назначение: Автоматически регистрирует детали выполнения функций: время вызова, имя функции, аргументы, результат и возникающие исключения.

Использование:
~~~
from decorators.logging import log
~~~
### Логирование в консоль
~~~
@log()
def greet(name: str):
    return f"Hello, {name}!"
~~~

### Логирование в файл
~~~
@log(filename="mylog.txt")
def calculate(a, b):
    return a + b
~~~

### Логирование ошибок
~~~
@log()
def divide(a, b):
    return a / b  # Может возникнуть ZeroDivisionError
~~~

### Особенности:

Поддерживает логирование в файл или в консоль.
Принимает уровень логирования (по умолчанию INFO).
Сохраняет полную трассировку ошибок.

## Тестирование
Проект покрыт модульными тестами с использованием фреймворка pytest. 
Тесты гарантируют корректную работу всех функций и устойчивость к некорректным входным данным.

Для запуска всех тестов в проекте выполните следующую команду в корневой директории проекта:

~~~
pytest
~~~
Покрытие тестами

src/widget.py: 100%

Описание тестируемой функциональности
### Модуль src/processing.py

Тесты проверяют логику обработки данных об операциях.

filter_by_state:

Корректная фильтрация списка операций по статусу (state).
Возврат пустого списка, если операций с заданным статусом не найдено.
Работа с пустым входным списком.

sort_by_date:

Правильная сортировка операций по дате в порядке убывания (по умолчанию) и возрастания.
Стабильность сортировки (сохранение порядка элементов с одинаковой датой).

### Модуль src/widget.py

Тесты проверяют функции для форматирования и маскировки данных, используемые в виджете.

mask_account_card:

Корректное определение типа (карта или счет) и применение соответствующей маски.
Обработка различных типов карт (Visa, MasterCard и т.д.).
Генерация ошибки ValueError при отсутствии номера в строке.

get_date:

Правильное преобразование даты из формата ISO (2024-03-11T02:26:18.671407) в формат ДД.ММ.ГГГГ.
Обработка дат как с микросекундами, так и без них.
Генерация ошибки при передаче строки, не являющейся датой.

### Модуль src/masks.py

Тесты проверяют низкоуровневые функции маскировки, которые используются другими модулями.

get_mask_card_number:

Корректная маскировка 16-значного номера карты в формат XXXX XX** **** XXXX.
Обработка номеров карт с пробелами.
Генерация ошибки ValueError для номеров неверной длины или с нецифровыми символами.

get_mask_account:

Корректная маскировка номера счета в формат **XXXX.
Обработка номеров счетов разной длины (главное условие — не менее 4 цифр).
Генерация ошибки ValueError для номеров короче 4 цифр или с нецифровыми символами.

## Модуль генераторов (src/generators.py)
Для работы с большими объемами данных реализован модуль generators. Он содержит функции, возвращающие итераторы 
(генераторы), что позволяет эффективно обрабатывать данные без загрузки их целиком в оперативную память.

### Функции:
filter_by_currency(transactions, currency_code)
Фильтрует транзакции по коду валюты.

~~~
from src.generators import filter_by_currency
~~~
~~~
usd_transactions = filter_by_currency(all_transactions, "USD")
first_two_usd = [next(usd_transactions) for _ in range(2)]
transaction_descriptions(transactions)
~~~
Последовательно извлекает описания операций.

~~~
from src.generators import transaction_descriptions

descriptions = transaction_descriptions(all_transactions)
print(next(descriptions)) # Выведет описание первой транзакции
card_number_generator(start, end)
~~~
Генерирует валидные номера карт в указанном числовом диапазоне.

~~~
from src.generators import card_number_generator

for number in card_number_generator(1, 5):
    print(number)
# >> 0000 0000 0000 0001
# >> 0000 0000 0000 0002
# ...
~~~

## Модуль utils

* **Функция:** `read_json_file(file_path)`
    * Описание: Читает данные о финансовых транзакциях из файла 
  формата JSON.
    * Аргументы:
        * `file_path` (str): Путь к файлу JSON.
    * Возвращаемое значение: Список словарей (`List[Dict]`), 
  где каждый словарь представляет одну финансовую операцию.
    * Особенности: 
      - Если файл не найден, пуст или содержит неверный формат данных
      (не список), функция возвращает пустой список.
      - Используется для загрузки исходных данных операций из файла
      `data/operations.json`.

## Модуль external_api

* **Функция:** `convert_to_rubles(transaction)`
    * Описание: Конвертирует сумму финансовой операции в рубли
  по текущему курсу валют.
    * Аргументы:
        * `transaction` (dict): Словарь с данными об одной транзакции.
      Обязательные ключи: `"amount"` (сумма) и `"currency"` (валюта).
    * Возвращаемое значение: Число типа `float`, представляющее сумму
  в рублях, или `None`, если валюта не поддерживается.
    * Алгоритм работы:
      1. Проверяет валюту транзакции. Если это RUB, 
      сумма возвращается без изменений.
      2. Для USD и EUR обращается к внешнему сервису
      [Exchange Rates Data API](https://apilayer.com/exchangerates_data-api) через HTTP-запрос.
      3. Полученный курс умножается на сумму транзакции.
    * Зависимости: Использует библиотеку `requests`. 
  Ключи доступа к API хранятся в переменных окружения `.env`.

## Конфигурация и безопасность

Для обращения к внешним API используются токены авторизации. 
Они никогда не должны храниться в коде или попадать в репозиторий.

* Все чувствительные данные (токены, пароли) хранятся в файле `.env`.
* В репозитории размещён только шаблон этого файла — `.env.example`. 
Он показывает структуру переменных, которые необходимо заполнить.
* Файл `.env` добавлен в `.gitignore`, поэтому он не попадает
под контроль версий.

Чтобы запустить приложение локально, скопируйте `.env.example` в `.env` и заполните его реальными значениями.
